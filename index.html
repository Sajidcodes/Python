The Calm, Confident Guide
to Your Python Final

Trace, don't memorize. Read the code the computer actually runs — not the one you wish it ran.

MODULE 00How to use this guide

If you can trace code by hand on paper — variable by variable, line by line — you can pass this exam. This guide builds that one skill across ten modules.

The deal

Every module follows the same rhythm: a concept in plain words, a mental model you can keep in your head, worked examples, a Bloom's ladder of questions from easy to hard, and an instant quiz with hidden answers so you can self-test honestly. None of the questions here are taken from the final — these are fresh examples that teach the same skills.

Knowing Python isn't one skill.

There are six levels of knowing:

Level 1 · Remember

Recall a fact. "What does len() do?"

Level 2 · Understand

Explain it. "Why does indexing start at 0?"

Level 3 · Apply

Use it on a new problem. "What does x[2] return here?"

Level 4 · Analyze

Take it apart. "Why is the loop running 4 times instead of 3?"

Level 5 · Evaluate

Judge it. "Which version of this code is clearer, and why?"

Level 6 · Create

Build something new. "Write a function that…"

Multiple-choice and "what's the output?" questions live mostly in Levels 1–4. Debugging questions live in Levels 4–6. Every module here gives you practice at every level.

★ The one habit that beats everything

Trace by hand. Take a pen, write down every variable, and update its value as you read each line. The computer doesn't run code in your head — it runs each line, one at a time, in order. Your job on this exam is to be the computer for two minutes at a time.

The trace table — your secret weapon

For any code that changes variables, draw a table: one column per variable, one row per line of code. After each line, write the new value (or repeat the old one if it didn't change). At the end, the answer is sitting in front of you.

# Code:
a = 3
b = 5
a = a + 1
b = a * 2
Lineab
a = 33—
b = 535
a = a + 145
b = a * 248

Final answer: a is 4, b is 8. No guessing, no panic. Just bookkeeping.

→ Study order

Go in order on your first pass — each module builds on the last. On your second pass, jump to the modules that felt shakiest. Aim for two full passes before exam day.

MODULE 01Lists — storing many things in order

A list is Python's way of putting many values in a single named container, in a specific order, so you can grab any one of them by its position number.

The concept in one sentence

A list is an ordered collection of items, written inside square brackets [ ], with items separated by commas.

groceries = ["milk", "bread", "eggs", "apples"]
★ Mental model

Picture an apartment building. Each floor holds one item. The ground floor is floor 0, not floor 1. So the first item lives at index 0, the second at 1, and so on. This is called zero-based indexing and it's true everywhere in Python.

The four things you must know about lists

1 · Items can be any type — including different types in the same list

pet = ["Rex", 3, "dog", True]
# Index:    0     1      2      3
# Type:    str   int    str    bool

2 · len() returns the count of items

len(groceries)   # → 4
len(pet)         # → 4
len([])          # → 0  (an empty list)

3 · Indexing grabs one item by position

pet[0]    # → "Rex"
pet[2]    # → "dog"
pet[-1]   # → True   (negative indices count from the end)
pet[-2]   # → "dog"

4 · Lists can hold other lists (nesting)

matrix = [[1, 2], [3, 4], [5, 6]]
len(matrix)      # → 3   (three inner lists, each counted as ONE item)
matrix[0]       # → [1, 2]
matrix[0][1]    # → 2   (first list, then position 1 inside it)
⚠ Most common pitfall

Confusing length (the count) with the last valid index (count minus one). A list of 4 items has length 4, but its highest index is 3. Trying my_list[4] on that list raises IndexError: list index out of range.

Instant Quiz · Lists

1. len(["sun","moon","stars"]) equals what?
3. Three items, so length is 3.
2. Given menu = ["pizza", "pasta", "salad", "soup"], what is menu[2]?
"salad". Counting from 0: pizza→0, pasta→1, salad→2.
3. What is menu[-1] for the list above?
"soup". -1 is always the last item, no matter how long the list is.

3. Two numbers and one inner list — three items total. The inner list counts as a single item even though it contains three numbers.
5. In data = [True, "yes", 1, 1.0], what is the type of data[3]?
float. The dot in 1.0 makes it a float, not an int.
6. In the same list, what is the index of "yes"?
1. True is at 0, "yes" is at 1.
7. If x = [5, 10, 15], what error do you get from x[3]?
IndexError: list index out of range. The list has length 3, so valid indices are 0, 1, 2. Index 3 doesn't exist.

MODULE 02Data types & the quotation-mark trap

Every value in Python has a type. The type tells Python how that value behaves — what you can do with it, and what happens when you try.

The five types you must recognize on sight

TypeWhat it isExamples
intwhole number0, 42, -7
floatnumber with a decimal point3.14, 0.0, -2.5
strtext in quotes"hello", '7', "True"
boolonly two values, no quotes, capital letterTrue, False
listordered collection in [ ][1, 2], ["a"], []

The type() function tells you which one

type(42)         # → <class 'int'>
type(3.0)        # → <class 'float'>   ← the dot makes it a float
type("42")       # → <class 'str'>     ← quotes make it a string
type(True)       # → <class 'bool'>
type([1,2])      # → <class 'list'>
★ Mental model — the quotation-mark switch

Quotation marks turn anything into a string. 7 is the number seven. "7" is a one-character string — a piece of text that happens to look like a digit. They look identical on screen but Python treats them as totally different things, like the difference between an actual cat and the word "cat".

The two famous traps

Trap 1 · True versus "True"

True (no quotes, capital T) is the boolean value true — one of only two boolean values in the language.
"True" (with quotes) is a four-character string: T, r, u, e. It happens to spell out "True" but Python doesn't care about its meaning; it's just text.

True == "True"     # → False  (boolean is not equal to a string)
type(True)         # → bool
type("True")       # → str

This matters: if user_logged_in == "True": will never be true if user_logged_in is the boolean True. Mixing them up is a silent bug — no error message, just the wrong behavior.

Trap 2 · 5 versus "5"

5 + 3          # → 8       (numbers add)
"5" + "3"      # → "53"    (strings concatenate — glue together)
5 + "3"        # → TypeError: unsupported operand type(s)
⚠ Why this matters on the exam

Whenever you see a value in code, identify its type first. Half the "what's the output?" questions hinge on whether something is a string or a number. The presence or absence of quotation marks is not decoration — it is the answer.

Instant Quiz · Types

1. type(False) is what?
bool. True and False are the only two booleans.
2. Is True == "True" true or false?
False. A boolean and a string are different types and are never equal, even when they look the same.
3. Is 5 == "5" true or false?
False. An int and a string are never equal in Python.
4. type(3.0) is what?
float. The decimal point makes it a float, even though the value is a whole number.
5. What is "10" + "20"?
"20"? No — it's "1020". The + operator on strings glues them end to end (concatenation), it doesn't add them as numbers.
6. What is type("True")?
str. Quotes make it a string. The text inside is irrelevant to Python.
7. Sketch the type of every item in mix = [10, 10.0, "10", True, [10]].
int, float, str, bool, list. Five values, five different types.

MODULE 03Lists vs Sets — order & duplicates

A list and a set both hold many items. They differ on two questions: does the order matter? and are duplicates allowed?

The two-line difference

ListSet
Written with[ ]{ }
Order kept?YesNo
Duplicates?AllowedRemoved automatically
Use it when…position matters or repeats matteryou only care about which unique items appeared

Worked example

votes = ["Alice", "Bob", "Alice", "Carol", "Bob", "Alice"]

print(list(votes))
# → ['Alice', 'Bob', 'Alice', 'Carol', 'Bob', 'Alice']
# Same six values in the same order — list keeps everything.

print(set(votes))
# → {'Alice', 'Bob', 'Carol'}
# Only the three unique names. Order may print differently each run.
★ Mental model

A list is a queue at the deli counter — order matters and the same person can take a number twice. A set is the guest list at the door — only names matter, and writing a name twice doesn't double-count anyone.

The classic exam pattern

Any time you see a list with repeats being passed to set(), the answer involves only the unique items. Any time it's passed to list(), the result is unchanged.

nums = [1, 1, 2, 3, 3, 3]
list(nums)   # → [1, 1, 2, 3, 3, 3]   (no change)
set(nums)    # → {1, 2, 3}            (duplicates gone)
len(set(nums))   # → 3                    (count of unique values)
⚠ Two things that surprise students
  • Sets print with curly braces { } — easy to confuse with a Python dictionary, which also uses { } but has key-value pairs separated by colons.
  • The order of items in a printed set can vary. Don't lose points trying to memorize which order — focus on which items appear and how many.

Instant Quiz · Lists vs Sets

1. What is set([1, 2, 2, 3, 3, 3])?
{1, 2, 3}. Duplicates removed.
2. What is list([1, 2, 2, 3, 3, 3])?
[1, 2, 2, 3, 3, 3]. Lists keep duplicates and order.
3. What is len(set("hello"))?
4. The unique characters are h, e, l, o — four of them. The repeated 'l' is dropped.
4. If scores = [80, 90, 80, 70, 90, 80], what does len(set(scores)) return?
3. Three unique scores: 80, 90, 70.
5. True or False: the set {3, 1, 2} always prints in the order 3, 1, 2.
False. Set order is not guaranteed and can vary.
6. Given names = ["Mia","Ravi","Mia","Sam","Ravi","Mia"], write the value of set(names).
{"Mia", "Ravi", "Sam"} — three unique names. Order may vary on screen.

MODULE 04Tracing variables — statements vs expressions

This is the single most exam-relevant skill in the course. If you master this module, you will pick up easy points everywhere else.

The two kinds of lines you'll see

Most lines of code fall into one of two camps:

  1. A statement that changes something — usually contains an equals sign. Example: x = 10, x = x + 1.
  2. An expression that just computes a value and throws it away — no equals sign on the outside. Example: x + 5, x + y.
★ Mental model — the silent calculation

An expression by itself is like solving a math problem on a whiteboard, then erasing it without writing the answer down. The calculation happened, but nothing was saved. The variables involved are not updated. The next time you read them, they still have their old values.

Worked example — read this slowly

balance = 100
deposit = 25
balance + deposit       # computes 125, but does NOTHING with it
print(balance)          # prints 100, NOT 125

Now compare:

balance = 100
deposit = 25
balance = balance + deposit   # NOW balance is updated to 125
print(balance)                # prints 125

The only difference is the balance = on the left. Without it, the computation is wasted.

The trace-table walkthrough — a step-by-step example

→ The exam pattern

Exam questions like "after these lines, what is the value of X?" reward exactly this skill. Read each line, ask "does this have an = on the outside?" — if yes, update the variable. If no, just compute the value and discard it.

The order trap — re-reading variables

When you see x = x + 1, Python reads the right side first, computes the new value, and then stores it on the left. So if x was 5, the right side computes 5 + 1 = 6, and x becomes 6.

x = 10
y = x        # y becomes 10. y is now its own variable.
x = 99       # changing x does NOT affect y.
print(y)     # still 10.
⚠ Watch for…
  • An expression with no = sitting on its own line — it does nothing visible to the variables.
  • Self-referential assignments like x = x + 1 — always evaluate the right side using the current values, then assign.
  • Re-assigning one variable doesn't reach back and change others that were copied earlier.

MODULE 05If / Else — making decisions

An if statement lets your program take different paths depending on whether a condition is true. The structure is simple, but indentation is everything.

The shape

if condition:
    # this runs only when the condition is True
else:
    # this runs only when the condition is False

Notice three things:

  1. A colon : at the end of the if line and the else line.
  2. The lines inside are indented (usually 4 spaces). Indentation is how Python knows what's inside the block.
  3. else has no condition of its own — it catches "anything else."

The comparison operators

OperatorMeansExampleResult
==equal to5 == 5True
!=not equal5 != 3True
<less than3 < 5True
>greater than3 > 5False
<=less than or equal5 <= 5True
>=greater than or equal5 >= 6False
⚠ The single most common bug in beginner code

Confusing = with ==. = is for storing a value into a variable. == is for comparing two values to ask "are these the same?" Inside an if, you almost always want ==.

Worked example

score = 75
if score >= 60:
    print("Pass")
else:
    print("Fail")
print("Done.")

Output:

Pass
Done.

The print("Done.") line is not indented under the if or else, so it runs no matter what.

The indentation drama

Compare these two snippets — only the indentation of the last line is different:

# Version A — print is INSIDE the else block
if True:
    print("yes")
else:
    print("no")
    print("finished")
# Output: yes
# Version B — print is OUTSIDE the else block
if True:
    print("yes")
else:
    print("no")
print("finished")
# Output: yes
#         finished
★ Mental model

Indentation in Python is like the bullet-point hierarchy in an outline. Lines at the same indent level belong to the same block. To know what runs, follow the indent. To know what doesn't, also follow the indent.

elif — chaining conditions

When you have more than two paths, use elif (short for "else if") between the if and the final else:

grade = 82
if grade >= 90:
    print("A")
elif grade >= 80:
    print("B")
elif grade >= 70:
    print("C")
else:
    print("F")
# Output: B
→ Crucial rule for elif chains

Python checks the conditions in order, top to bottom, and stops at the first one that is true. Even if a later condition is also true, it will not run. Order matters!

MODULE 06and / or / not — combining conditions

Sometimes one condition isn't enough. Boolean operators let you combine multiple comparisons into a single yes-or-no question.

The three operators

OperatorReturns True when…
andBOTH sides are True
orAT LEAST ONE side is True
notThe single thing on its right is False

Truth tables — the only thing to memorize

ABA and BA or B
TrueTrueTrueTrue
TrueFalseFalseTrue
FalseTrueFalseTrue
FalseFalseFalseFalse
★ Mental model

and is strict — it's like a job that needs two signatures. Both must approve. Miss one, the answer is no.
or is generous — it's like getting into a park if you have an adult ticket OR a child ticket. Either one gets you in.
not just flips True to False and back, like a light switch.

Worked example

age = 20
has_id = True

if age >= 18 and has_id:
    print("Welcome")
else:
    print("Sorry")
# Output: Welcome  (both conditions are True)

Now change one thing:

age = 20
has_id = False

if age >= 18 and has_id:
    print("Welcome")
else:
    print("Sorry")
# Output: Sorry  (one side is False, so AND fails)

Swap and for or:

age = 20
has_id = False

if age >= 18 or has_id:
    print("Welcome")
# Output: Welcome  (at least one side is True)

The "or" trap

In English, "or" sometimes means "one or the other but not both." In Python, or is true if either side is true or both are. There's no exclusion.

Combining and/or — read it like math

When you mix them, and binds tighter than or (similar to how × binds tighter than + in math). When in doubt, add parentheses.

a = True
b = False
c = True

a or b and c
# Read as: a or (b and c)
# = True or (False and True)
# = True or False
# = True
⚠ Watch for…
  • Forgetting to repeat the variable: x == 1 or 2 does NOT mean "x is 1 or 2." Write x == 1 or x == 2.
  • Using English "and"/"or" instead of lowercase Python keywords. AND, And, and && are not Python.

Instant Quiz · Booleans

1. True and False equals?
False. and needs both to be True.
2. True or False equals?
True. or needs at least one True.
3. not True equals?
False. not flips it.
4. With x = 7, what is x > 5 and x < 10?
True. Both conditions hold (7 is greater than 5 AND less than 10).
5. With a = 3, b = 3, c = 7, what does this print?
if a == b or b == c:
    print("match")
else:
    print("no match")
match. a == b is True (both 3), so the or short-circuits to True. b == c doesn't even need to be checked.
6. With p = 5, what does p == 5 or 0 evaluate to?
True, but for the wrong reason. Python reads it as (p == 5) or 0, which is True or 0, which is True. This LOOKS like it works, but if you wrote it intending "is p equal to 5 or 0?", you'd be wrong — try p = 0 and the same expression returns 0, not True.
7. Write a condition that's True only when n is between 10 and 20 inclusive.
n >= 10 and n <= 20 (or the more Pythonic 10 <= n <= 20).

MODULE 07Loops — doing something many times

A for loop walks through a collection of items one at a time and runs the same block of code for each one.

The shape

for variable in collection:
    # this block runs once per item
    # the variable holds the current item

A first example, traced step by step

for color in ["red", "green", "blue"]:
    print(color)

Each pass through the loop, color takes on the next item:

Passcolor is…Output line
1"red"red
2"green"green
3"blue"blue

Nested loops — a loop inside a loop

For every single pass of the outer loop, the inner loop runs completely from start to finish.

for fruit in ["apple", "pear"]:
    for color in ["red", "yellow"]:
        print(fruit, color)

If the outer list has 2 items and the inner list has 2 items, the print runs 2 × 2 = 4 times:

apple red
apple yellow
pear  red
pear  yellow
★ Mental model — odometer

Nested loops behave like an odometer in a car. The inner loop is the rightmost wheel — it spins through all its values before the outer wheel clicks forward by one. Outer = slow wheel. Inner = fast wheel.

The big surprise — the loop variable lives on after the loop

This catches every student. After a for loop ends, the loop variable still exists, holding the last value it had.

for n in [1, 2, 3]:
    print("inside:", n)
print("outside:", n)
# Output:
# inside: 1
# inside: 2
# inside: 3
# outside: 3      ← n is still 3 after the loop ends

For nested loops, both the outer and inner variables persist with their last values:

for i in [1, 2]:
    for j in [7, 8, 9]:
        pass            # do nothing this round
print(i, j)            # prints: 2 9
⚠ The most-tested trap on this topic

Watch the indentation of any print after a loop. If it's indented under the loop, it runs every iteration. If it's at the same level as the for, it runs once at the end — and the loop variable now holds the last value from the loop.

Counting how many times a nested loop prints

If the outer collection has m items and the inner has n items, the innermost code runs m × n times. Always do the multiplication.

for a in [1, 2, 3, 4]:
    for b in [5, 6]:
        print("hi")
# prints "hi" exactly 4 × 2 = 8 times

range() — making numbers without typing them all

range(n) produces the numbers 0 up to (but not including) n. So range(4) gives 0, 1, 2, 3.

for i in range(4):
    print(i)
# Output:
# 0
# 1
# 2
# 3

MODULE 08Nested if / elif / else — the indent dance

When if-statements live inside other if-statements, indentation tells the whole story. This module is mostly about reading carefully.

Two crucial rules

  1. An elif or else attaches to the nearest if at the same indent level above it.
  2. If the matching if was True, all its elif and else branches are skipped.

Worked example — read indentation, not intent

n = 25
if n > 10:
    print("A")
    if n > 20:
        print("B")
    print("C")
elif n > 5:
    print("D")
else:
    print("E")
print("end")

Walk through it slowly:

  1. n > 10 is True (25 > 10), so we enter the first if block.
  2. Print "A".
  3. Check the inner if n > 20. True (25 > 20), so print "B".
  4. Print "C" (still inside the outer if block).
  5. The elif and else are skipped entirely because the original if was already True.
  6. Print "end" (no indentation, runs no matter what).

Output:

A
B
C
end
★ Mental model

An if/elif/else chain is one decision with multiple options. Pick the FIRST one that matches and skip the rest. A separate, indented inner if-statement is a totally different decision happening inside the chosen branch — and it can have its own elif/else without affecting the outer chain.

The "independent ifs" trap

Three separate if statements (no elif) work very differently from a single chain.

# Version A — three independent ifs
score = 95
if score >= 60: print("D or higher")
if score >= 80: print("B or higher")
if score >= 90: print("A")

# Output:
# D or higher
# B or higher
# A          ← all three run because they are independent
# Version B — one if/elif chain
score = 95
if score >= 60: print("D or higher")
elif score >= 80: print("B or higher")
elif score >= 90: print("A")

# Output:
# D or higher    ← only the first true branch runs
⚠ Watch for…
  • An else that looks like it should match an outer if but is actually attached to the inner one. Indentation decides — read it like a building floor plan, not like English.
  • Conditions in the wrong order in an elif chain. Putting a wider condition first makes the narrower ones unreachable.

MODULE 09Functions, parameters, return & while

A function is a named block of code you can run again and again, optionally passing it different inputs each time. Functions are the second-most-tested topic on this exam, after tracing.

Anatomy

def greet(name):          # <-- function header. "name" is the PARAMETER.
    message = "Hi, " + name  # <-- function body (indented)
    return message          # <-- send a value BACK to whoever called it

result = greet("Sara")       # <-- the call. "Sara" is the ARGUMENT.
print(result)               # <-- prints: Hi, Sara

★ Mental model

Calling a function is like handing a coupon to a vending machine. The coupon is your argument. Inside the machine, the coupon is given a slot name (the parameter). The machine does its work and either drops a snack out the bottom (the return) or just lights up an info display (a print).

return versus print — completely different jobs

This is the most-confused pair in the whole course. They look similar but they do opposite things.

Argument order matters

When you call a function with positional arguments (no name labels), Python matches them left to right with the parameters. Swapping the order swaps the meaning.

def divide(top, bottom):
    return top / bottom

divide(10, 2)    # top=10, bottom=2  → 5.0
divide(2, 10)    # top=2,  bottom=10 → 0.2
⚠ The variable-name swap trap

If you have variables named a and b at the top of your script and a function with parameters also named a and b, calling my_func(b, a) sends them in swapped order — the function's a receives your global b's value, and vice versa. Look at the call, not the names.

Local scope — what happens inside the function, stays inside

Variables created or changed inside a function are local to that function. They do not affect variables of the same name outside.

x = 10

def change(x):
    x = 999     # this x is local to the function
    print("inside:", x)

change(x)
print("outside:", x)
# Output:
# inside: 999
# outside: 10     ← unchanged!

while loops

A while loop keeps running as long as a condition is True. You usually need to update something inside the loop, otherwise it runs forever.

n = 3
while n > 0:
    print(n)
    n = n - 1     # crucial — without this, infinite loop
print("liftoff!")
# Output:
# 3
# 2
# 1
# liftoff!

⚠ Infinite loops

Forget to change the condition variable inside the loop and your program will run forever. Common cause of "my code froze." Always look at the condition first and ask "what makes this eventually become False?"

MODULE 10The debugging mindset

Debugging is the discipline of asking what the code actually does, not what you wished it did. The exam will hand you buggy code and ask you to predict its real output. Here's how to win that game.

The five-step debugging method

  1. Read the code line by line. Don't skim. Resist the urge to "see what it's trying to do."
  2. Build a trace table for any variables that change.
  3. Check indentation carefully — what's inside which block?
  4. Look for the usual suspects (see list below).
  5. Predict the output line by line, then propose a fix.

Worked debugging walkthrough

Here's a buggy function. The author intended: "Add up all the numbers and return the total."

def add_all(numbers):
    total = 0
    for n in numbers:
        total + n          # BUG #1
    return Total            # BUG #2

print(add_all([1, 2, 3]))

Walking through with the debugging method:

  1. Bug #1: total + n is an expression with no assignment. It computes a value and throws it away. total stays at 0 forever. (Module 4 trap.)
  2. Bug #2: Total with a capital T is a different name from total. Python is case-sensitive, so this raises NameError: name 'Total' is not defined.

The fix

def add_all(numbers):
    total = 0
    for n in numbers:
        total = total + n   # now total actually grows
    return total           # lowercase, matches the variable name

print(add_all([1, 2, 3]))   # → 6
★ Mental model — be the computer

Imagine you are the world's most literal employee. Your job is to do exactly what each line says, in order, no creativity allowed. The bugs aren't yours to interpret — they're yours to execute. The right answer is whatever a literal-minded employee would produce, even if it's clearly not what the author wanted.

MODULE 12One-page cheat sheet

Print this. Read it the morning of the exam. Then close it and trust your training.

Lists

  • Made with [ ], items in any order, can mix types, can nest.
  • len(my_list) = number of items.
  • Index starts at 0. Last item is at len - 1, or use -1.
  • Out-of-range index → IndexError.

Types

  • int (no dot), float (has dot), str (has quotes), bool (only True/False), list (has [ ]).
  • type(value) reveals the type.
  • True ≠ "True". 5 ≠ "5". Quotes change everything.
  • "a" + "b" = "ab" (glue). 1 + 1 = 2 (math).

Sets

  • Made with { }, no duplicates, no guaranteed order.
  • set(my_list) deduplicates. len(set(...)) counts unique items.

Tracing

  • Line with = outside → updates a variable.
  • Line without = → computes a value and discards it.
  • x = x + 1 → evaluate the right side first using current x, then store.
  • Use a trace table: one column per variable, one row per line.

If / Else / Elif

  • Indentation defines the block. Colons end the if, elif, and else lines.
  • An if/elif/else chain runs at most one branch — the first true one.
  • Several independent ifs can each run separately.
  • Use == (compare), not = (assign), inside conditions.

Boolean operators

  • and — both must be True.
  • or — at least one True.
  • not — flips True/False.
  • Always rewrite x == 1 or 2 as x == 1 or x == 2.

Loops

  • for var in collection: — runs once per item.
  • Nested loops: inner runs in full for every outer step. Total = m × n.
  • Loop variable still exists after the loop, holding the last value.
  • range(n) gives 0 to n−1.
  • while cond: — must change something inside or run forever.

Functions

  • def name(parameters): — define. name(arguments) — call.
  • Parameter = name in the def line. Argument = value in the call.
  • Order of arguments matters.
  • return sends a value back; print only shows.
  • No return → function returns None.
  • Variables inside a function are local; they don't change outer variables of the same name.

Debugging mindset

  • Be the computer: literal, line by line, no assumptions.
  • Build trace tables for variables.
  • Suspect: = vs ==, indent levels, missing assignment, missing return, independent ifs vs elif chains, swapped argument order, type mismatch.

Exam-day strategy

  1. Read the question all the way through before writing.
  2. If it's a tracing question, draw the trace table immediately.
  3. If it's a function question, circle the parameters and the call's arguments and check the order.
  4. If it's a debugging question, ignore intent and trace what the code actually does.
  5. Watch the indentation like a hawk on every print after a loop or if.
  6. If stuck, skip and come back. Easy points first.
✓ Final encouragement

Sleep before the exam — caffeine can only do so much. Watch out for indentation — Python is strict, not the professor! Don’t argue with SyntaxError; it always wins. Avoid naming your variables l or O — they look like 1 and 0, and you will regret it. Spaces are for people; underscores are for Python. Remember: semicolons are optional, but commas in lists are mandatory. Read all questions carefully — even the sneaky ones hiding at the bottom! Test your code with small examples (and no, “it works on my machine” is not an excuse). elif ≠ else if (we’re not in C++ or Java anymore, folks).
